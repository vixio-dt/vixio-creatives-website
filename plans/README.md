## Direction findings (options for the maintainer, not ranked against bugs)

- **Per-work detail pages**: `SLATE-DETAIL-*` ids are already typed in
  `lib/slate.ts:11-13` and specced in PLACEHOLDER-ASSETS.md, but explicitly
  out of scope in RESTRUCTURE-PLAN-V2.md. Becomes pressing at first release
  (press kits, link sharing). Effort M; needs an ADR first.
- **"Watch"/"Shop" labels have no destinations**: `lib/copy.ts:133-134`
  reserves both verbs for released work; no commerce or viewing surface
  exists. Strategic call: build the surface before first release, or soften
  the labels. Effort L (build) / S (re-copy).
- **Screening dates**: newsletter copy promises "a screening date"
  (`lib/copy.ts:138`); the slate data model has no screenings field. Cheap to
  add to the model when the first festival date is real. Effort M.
- **Released/notes archive**: Notes lane is deferred by ADR-07 and the data
  model carries statuses that imply a future archive view. Defer until real
  content exists (matches ADR-07's own reasoning).

## Findings considered and rejected

- **CSRF on /api/contact**: no cookies or sessions exist to ride; a cross-site
  POST is equivalent to any anonymous submission. Not a CSRF surface. Spam
  hardening (honeypot/rate limit) noted as a deferred follow-up in plan 002.
- **Resend "header injection"**: Resend is a JSON HTTPS API, not raw SMTP;
  newlines in `subject` do not become headers. Subject hygiene folded into
  plan 002 as cleanup, not a vulnerability.
- **Supabase NEXT_PUBLIC_ fallback in lib/supabase.ts as secret exposure**:
  the anon key is public by design under RLS, and the module is only imported
  server-side. By-design; also the file is frozen by AGENTS.md.
- **"Form stuck in pending" (missing .finally)**: the `await fetch` sits in
  try/catch; any rejection reaches `setStatus('error')`. Not a bug.
- **"Newsletter lacks client-side email validation"**: its form does not set
  `noValidate`, so native `type="email" required` validation applies. The
  *server-side* gap is real and lives in plan 002.
- **Duplicate-submission dedup (UUID + server window)**: the disabled submit
  button suffices for a contact form; server dedup is over-engineering.
- **Studio page server/client splitting**: every studio component animates,
  the page prerenders statically, and the bundle is small; splitting adds
  hydration complexity for negligible gain.
- **LogoTransition scroll-jank / reduce piecewise segments**: transform/
  opacity/filter only, gated on reduced motion, spec'd by ADR-16. Profiling
  before optimizing; no evidence of jank.
- **useReducedMotion re-render overhead**: speculative; no measurable signal.
- **Husky pre-commit hooks**: CI plus the one-command `npm run verify` gate
  (plan 004) covers enforcement without a new dependency.
- **README architecture prose, PLACEHOLDER-ASSETS codename disclaimer**:
  marginal value; the docs are internal and accurate enough.
- **dist/ vs .next/ confusion**: `distDir: 'dist'` is explicit in
  next.config.ts and documented in AGENTS.md. Not a finding.
